# Changelog

## 0.3.0 (2026-10-09)

- `land.py` caps changes in flight per repository (`init --cap`, `cap N`), refuses to renew an expired lease into an overlap or past the cap, and adds `lease check`, `lease renew --if-live`, and `status --holder`.
- `brigade.py open` claims its directory with `mkdir` and no `exist_ok`. The process that created the directory writes the tables, `menu.md`, and `house-rules.md`, then writes `restaurant.json`, and only then prints `opened`. Another process waits up to one second for that file and does not write those files. When the file is present but not valid JSON after that second, `open` exits 1 with `brigade: <file> is not valid JSON` and leaves the file unchanged. When that file names another project root, `open` exits 1 with `brigade: <dir> already holds a coordinator for <other root>; pick another --name` and leaves the file unchanged. After `opened` or `exists`, `open` prints each sibling on the same project root, with its thread, purpose, and what it does not take. An existing coordinator prints `thread <id> already recorded` when a thread is recorded. `brigade.py set --thread` refuses to replace that thread unless `--replace` is passed. A coordinator thread is launched only when `open` printed `opened`. The first service reruns `open` and compares sibling purposes with `menu.md`. Standing orders name the hot shared files `CHANGELOG.md`, `README.md`, and `docs/guide.md`. A change adds its changelog bullet under `changes/` and edits `README.md` or `docs/guide.md` only when its ticket is about them, or when it removes or renames something they name. Other doc edits are follow-ups batched into one docs item.
- `scripts/check.py` checks a catalog heredoc only between `<<'JSON'` and a closer line that is `JSON` and nothing else. It rejects an indented closer and a closer with trailing whitespace. `$interrogate`, `$arena`, `$architect`, and `$swarm` pass a large catalog in that quoted heredoc.
- The pull request template asks for one bullet in `changes/<encoded branch>.md`, as `CONTRIBUTING.md` describes. `.gitignore` ignores `/.agents/`, `/.cursor/`, and `/skills/poteto-mode/scripts/node_modules/`.
- Each intake source has one owning brigade coordinator. `brigade.py open --intake` records it when it creates a coordinator, and `set --intake` changes it. Both refuse a source a sibling owns. `open` on an existing coordinator keeps its intake. `ticket add` refuses a source this coordinator does not own and a ref that is still live here or in a sibling, following moved tickets to the end of their chain. `ticket move <id> --to <sibling>` hands a waiting ticket to a sibling through its `inbox/`, and `ticket take` files it once, keyed by handoff id, and finishes a take a crash interrupted. Every write holds a lock on `restaurant.lock`, no command holds it while it waits on stdin or `land.py`, an append drops a killed append's unfinished tail before it writes, and a table line that does not parse stops any command run with `--at` with `brigade: <table> line <n> is malformed; fix or remove it`. `watch`, `status`, and `close` show handoffs until they are taken.
- A refused `brigade.py fire` records the paths and branch it was given, and `watch` says whether a lease, the repository cap, or the worker cap still blocks it, with the number of workers that are running. The unblocked line is a shell-quoted `fire` command. Each option is one `--name=value` word, so a value that starts with `-` stays that option's value, and the command includes `--branch` when one was recorded. `fire` leases `changes/<branch>.md` for the branch that attempt will use, including when `watch` rechecks a blocked ticket. `open --workers` and `set --workers` cap how many items can be in progress or in review, and a missing value reads as 2. `dish --lease` and `dish --paths` record a lease claimed again. A release that fails names the lease and the landing queue's diagnostic, and a failed lease check keeps that diagnostic.
- `brigade.py watch` renews the lease of every in-progress, in-review, passed, sent-back, or parked item with `land.py lease renew --if-live`, prints a line for an expired, released, or unreadable lease and for every item not merged or dropped, and updates `lastActivityAt` after a pass that renewed every live lease. For a passed or queued item it reads the queue entry at the item's exact full SHA through the new `land.py status --holder <h> --sha <sha>` filter and says whether it landed, awaits merge, bounced, or was already submitted. `dish --state dropped` releases the item's lease, and refuses without `--stopped <run id>` while a worker thread is recorded. `restaurant.json` gains `generation`: `set --thread` records 1 and `--replace` adds 1, `status` prints `owner <thread>@<generation>`, and every write then needs `--owner <thread>@<generation>`, including a ticket move's handoff into a sibling's inbox and a ticket take's inbox deletion. `land.py owner --prefix <p>/ --generation <n>` raises a floor that `lease claim`, `lease renew`, `lease release`, and `submit` enforce through `--owner`. Upgrade: a coordinator opened earlier has no `generation` and keeps working without `--owner`. Run `brigade.py set --thread <its recorded thread>` once to record generation 1, then pass `--owner <thread>@1` on every write.
