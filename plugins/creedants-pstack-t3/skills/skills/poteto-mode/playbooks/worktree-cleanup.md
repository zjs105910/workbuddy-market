### Worktree and simulator cleanup

**You own the disk and the safety gate.** Prune merged or abandoned git worktrees and stale iOS simulators to reclaim space. Deletion is irreversible, so every step guards against deleting something in use or holding uncommitted work.

[The runtime's Modes section](../../pstack-runtime/SKILL.md#modes) sets the mode lines of every brief this playbook writes and how its spawns run in light mode.

1. Snapshot and audit. Record `df -h /`, then run `scripts/worktree-audit.sh <repo>` (principle-build-the-lever). It reads paths from `git worktree list`, never hand-typed, since a hand-typed `myrepo-worktrees/x` misses one that lives at `~/.t3/worktrees/<project>/x` or under the directory in Settings (principle-encode-lessons-in-structure). It classifies each worktree by size, last commit age, last HEAD activity (`ACTIVE`), merge state against trunk, uncommitted work, upstream state, PR state, and whether T3 manages that path (`T3=yes`), then suggests a bucket. A path is managed when it sits under `<T3 home>/worktrees`, or under `worktreesDirectory` or `previousWorktreesDirectories` in `<T3 home>/userdata/settings.json`. `--t3-worktrees` or `T3_WORKTREES` replaces those settings roots for one run, and the default directory still counts. It runs on Linux and macOS and never deletes anything. Run it once per repository that owns worktrees.
2. The bucket is advice, not permission. T3's thread bindings are the real artifact (principle-prove-it-works), and the script cannot see them. Build the bound set with T3's tools. List the project's threads with `t3_thread_list`, once with `settled: false` and once with `settled: true`, and pass `includeSubagents: true` so child task threads count. Call `t3_thread_read` with `limit: 1` on each thread and record its `status`, `settled`, `branch`, and `worktreePath`. Cross-check each candidate path and branch against that set, and against `t3_worktree_list` with `query` set to the branch. Call `t3_worktree_status` so you never prune this thread's own worktree. Threads from other projects are not visible, so run the cleanup from a thread in each project that owns worktrees, or ask the user about worktrees no listed thread explains.
3. Verify usage before deleting. A worktree bound to an active thread is in use. Active means a status of `preparing`, `queued`, `starting`, `running`, or `waiting`. Never prune it, whatever its bucket. A worktree bound to an unsettled thread that is idle or finished is held until the user confirms, since an unsettled thread is one the user still keeps in the active list. Also hold a worktree whose branch an active thread names, a worktree a pending request references (`t3_pending_request_list`), and a worktree an enabled schedule touches (`list_scheduled_tasks`). For every `verify-recent` row, or anything you doubt, read the bound threads' last messages with `t3_thread_read`, and fan child tasks out for long ones (principle-guard-the-context-window, threads are bulk). An active thread spawns arena and repro trees into sibling worktrees through child tasks, and those are in use even when their names never appear in the sidebar. Trace them through the parent's `childThreadId` threads. A worktree bound only to settled threads, clean, and merged is a candidate.
4. Pause on irreversible loss. `wip:N` is N tracked uncommitted edits. Show the diff and get a decision first, since removing a clean worktree is recoverable from its branch but uncommitted work is gone. `scratch:N` is untracked throwaway, safe to drop, but name the files. `aheadN` is N commits the upstream lacks. Name the branch, since the branch ref survives removal but nothing else holds those commits off this machine. Per Autonomy, clean and merged and not-in-use proceeds. `wip` and in-use pause.
5. Prune the confirmed set. Per path, `git worktree remove --force <path>`. If the dir survives on ignored build artifacts, `rm -rf` it, then `git worktree prune`. A `prunable-missing` row needs only `git worktree prune`. Branch refs survive, so no commits are lost. Confirm with `df -h /` and re-list.
6. Simulators and other reclaimers. Run the simulator steps only on macOS with Xcode tools present (`command -v xcrun` succeeds). Skip them elsewhere. Simulators are usually the next-biggest win. `xcrun simctl --set testing delete all` (XCTestDevices clones), `xcrun simctl delete unavailable`, and `xcrun simctl runtime list` then `runtime delete <id>` for old runtimes. More when needed: Xcode `DerivedData` and `iOS DeviceSupport` on macOS, and package caches on any OS (pnpm, uv, brew, yarn, cargo, `~/.cache` on Linux). Clear only caches the user has not said to keep. Never touch `~/.t3` outside `git worktree` commands, since T3 keeps thread state there.

This is the one playbook that deletes user state with no code review to catch a slip, so the gates above are the review.

**Reply:** `df -h /` before and after with space reclaimed, the worktrees pruned, and a one-line reason for each held back (bound to which thread, or uncommitted work).
