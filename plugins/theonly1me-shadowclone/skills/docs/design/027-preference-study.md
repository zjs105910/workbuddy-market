# Preference evaluation

## Contract

The benchmark measures whether coding agents follow engineering preferences under five fixed setups. Existing skills provide the baseline. Handwritten intended preferences provide a reference for learning fidelity. Actual learned guidance stays unchanged throughout scoring.

Freeze 24 synthetic tasks across eight equally weighted families: comments, types, API conventions, Git authorization, answer length, test-first behavior, PR structure, and scope/lifecycle. Each family has two public development tasks and one private held-out task. Author correction sessions, intended guidance, and the skill library separately. Include repeated examples, conditional rules, temporary exceptions, superseded instructions, and insufficient evidence.

Keep repository requirements authoritative. Rank current requests above personal defaults. Test explicit commit and longer-answer requests. Use only offline Git and GitHub fixtures for remote actions. A separate experiment compares a 20-skill library, with and without native routing, on twelve tasks.

## Delivery and learning

Use the existing initialization, consent, ingestion, `resolveRedacted`, reconciliation, publication, and native delivery paths. Do not inject a combined profile into active skills. Preserve manual guidance and file ownership.

Three independent preparations use one pinned Codex learner and identical synthetic inputs. Each scored repetition receives a different preparation. Reuse completed preparation outputs only when the learning source, runtime, corpus, model, and initial guidance match. Report published, missing, pending, and unsupported guidance without substituting intended answers.

Create the synthetic repository observations before ingestion. Then the corrections have a verified scope. Validate actual adapter text, redacted references, and paired steering episodes offline. Optional programmatic learning limits must match the explicit call ceiling. Ordinary learning keeps its existing defaults.

## Execution and evidence

Private held-out tasks, frozen suites, learned environments, native transport, and receipts stay outside every checkout. Public material contains task hashes, coverage, and aggregate scores. Preparation, review, and offline validation make no authenticated calls. Every authenticated phase needs an explicit exact scope and invocation ceiling.

Save ownership and invocation reservations before dispatch. A resume revalidates fingerprints and keeps completed results. Permit one replacement only for a confirmed infrastructure failure. Charge both attempts and keep both. Stop dispatch on unresolved infrastructure or provider holds. Ordinary model failures do not authorize retries.

Protect grading answers and manual guidance through native permissions. Give each task a disposable workspace and home. Verify read-only modes, private temporary paths, cleanup, and native Codex permissions without model calls. Keep private stage diagnostics. Then people can diagnose failures without blind reruns.

## Scoring

Within each task, score the required checks for its assigned preference family. Average repetitions and tasks within each family, then average the eight families. Missing execution leaves the headline incomplete. Correctness, protected-guidance safety, skill selection, and learning coverage have separate fields.

Count all whitespace-separated final-answer tokens, including code and fences. The default permits eighty tokens. An explicit longer request overrides it. Primary intervals resample the three matched repetition/preparation groups with the task mix fixed.

## Implementation sequence

1. Define the tasks, correction corpus, intended guidance, held-out contract, and routing library.
2. Add case review, freeze gates, private artifact storage, and invocation ceilings.
3. Prepare manual, routed, handwritten, and learned environments through the existing product paths.
4. Extend native execution with private diagnostics, protected guidance, durable accounting, and holds.
5. Add family-weighted reports, matched comparisons, and preparation reuse.
6. Validate graders, scope, isolation, recovery, fingerprints, and manual preservation offline.
7. Run the separately approved model cohorts and audit saved graded responses.
8. Publish one current evaluation page with clear setup and model names, detailed family scores, and concise measurement limits.

The public documentation presents one current evaluation. Internal protocol identifiers preserve saved receipts and compatible callers. Private execution evidence remains immutable. Changes to public presentation do not rescore the recorded study.

## Completed study

All planned sessions finished on GPT 6.1 Sol, GPT 6 Luna, Claude Sonnet 5.5, and Claude Opus 5.5. The [results](../../evals.md) keep fixed denominators and original verdicts. A bounded audit of saved responses supports the adherence interpretation. It also identifies limits in correctness, routing attribution, and toolchain consistency. These results describe synthetic preference delivery. They do not qualify production throughput or broad security claims.
