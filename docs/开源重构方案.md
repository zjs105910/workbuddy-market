## 0. 不可破坏的约束（先于一切）

以下条目来自本项目 23 条工程约定和验证清单，重构期间**每一条都继续生效**：

1. **每阶段收尾必跑验证四件套**：`py_compile` 四文件 → `selftest.py` 全绿 →  
   `launcher.py --status` 深度自检通过 → `launcher.py --recover` 补记 0 项。
2. **`import market_core`、`import market_server` 不能断**（兼容层方案见 §3）。
3. **版本号唯一来源是 `MARKET_VERSION`**，本轮重构 = 次版本 +1 → **v2.7.0**。  
   评审建议的 `0.1.0` 起步号与本项目「每轮评审 +1」的既定约定冲突，**不采纳**；  
   改为把它改名为 `PROJECT_VERSION` 并保留 2.7.0（见 §6）。
4. **事务/恢复/fail-closed 语义一行都不许变**。拆分是搬代码，不是改行为。
5. **README 每轮一节不能欠账**（工程约定 23）：v2.7 轮必须同步写第十七节。
6. 运行时目录迁移（§2）本身也要幂等 + 原子 + 写日志，不允许「迁移脚本跑一半」状态。

## 2. P0-①：运行时目录与仓库分离

### 2.1 三层根目录（paths.py 的核心）

```python
# src/workbuddy_market/paths.py
import os
from pathlib import Path

def _env(name: str, deprecated: str):
    """新名优先，旧名兼容但打一次警告。"""
    v = os.environ.get(name)
    if v is not None:
        return v
    v = os.environ.get(deprecated)
    if v is not None:
        import sys
        print(f"WARNING: {deprecated} is deprecated; use {name} instead.",
              file=sys.stderr)
        return v
    return None

# ① 市场仓库根（产品）：config / marketplace.json / plugins / web
MARKET_ROOT = Path(_env("WBM_MARKET_ROOT", "GHPM_MARKET_ROOT")
                   or _repo_root()).resolve()

# ② 运行状态根（环境）：state / tx / trash / backups / ownership / locks / logs
STATE_HOME = Path(
    _env("WBM_STATE_HOME", "GHPM_MARKET_ROOT")   # 见下方「跟随规则」
    or (Path.home() / ".workbuddy-market")
).resolve()

# ③ WorkBuddy 家目录：skills / known_marketplaces.json
WB = Path(_env("WBM_HOME", "GHPM_HOME") or (Path.home() / ".workbuddy")).resolve()
```

**跟随规则（测试隔离的关键）**：当只有旧的 `GHPM_MARKET_ROOT` 被设置时（老的自检/harness），  
`STATE_HOME` 跟随 `MARKET_ROOT` —— 即完整复刻今天的行为，一行老代码都不用改。  
三件套 `WBM_MARKET_ROOT` / `WBM_STATE_HOME` / `WBM_HOME` 齐备后，语义各自独立。

### 2.3 一次性迁移 `migrate_runtime_files()`

- 触发：进程启动（cli / server / selftest 入口）时调用，幂等。
- 规则：repo 根存在旧文件 且 STATE_HOME 无对应 → `os.replace` 原子搬入 + `log("info", "runtime_migrated", ...)`；  
  两边都在 → **以 STATE_HOME 为准，repo 侧文件保留不动**（绝不删用户文件，工程约定 5）。
- repo 根下的 `.lock` 文件不迁移，直接废弃重建（锁无持久语义）。
- 自检改用三件套临时目录，迁移逻辑在临时环境里也要有一组用例覆盖。

### 3.2 兼容 shim（唯一正确的写法）

```python
# market_core.py（瘦身后 ~60 行）
"""兼容层：所有实现已迁至 workbuddy_market 包。将在 v3.0 移除。"""
import warnings
from workbuddy_market import *          # noqa: F401,F403
from workbuddy_market import __all__ as _all
# 显式再导出供 IDE / monkeypatch 发现：
from workbuddy_market.version import *   # noqa: F401,F403
from workbuddy_market import paths, config, transactions, installer  # 常用子模块
```

**必须写进方案的警告**（这是本次拆分最大的隐性风险）：

selftest 有大量 `core.GHPM_PY = fake` 这类 **模块属性 monkeypatch**  
（selftest.py:2225/2234/2256/2268）。shim 的 star-import 是**值拷贝**：  
patch `core.X` 不会影响包内部对 `X` 的引用。因此：

- 测试迁移的同一批 PR 里，所有 monkeypatch 目标必须从  
  `core.符号` 改为新模块的 `符号`（如 `workbuddy_market.paths.REMOTE_JOB_TOOL`）；
- 包内部代码引用这些「可注入点」时统一走模块命名空间  
  （`from . import paths` 后用 `paths.REMOTE_JOB_TOOL`），不许 `from .paths import REMOTE_JOB_TOOL`  
  后直接用裸名——否则 patch 失效，测试会假绿。
- `main()` 兜底：若 `import market_core` 时检测到 `WBM_`/`GHPM_` 旧环境变量，  
  打 deprecation 提示（§5）。


## 5. P0-⑧：解除 GHPM 耦合

核对结果：核心代码里 GHPM 痕迹共 3 类，处理方式不同——

| 位置                                                                 | 现状                                 | 处理                                                                                 |
| ------------------------------------------------------------------ | ---------------------------------- | ---------------------------------------------------------------------------------- |
| 环境变量 `GHPM_MARKET_ROOT` / `GHPM_HOME`（market_core.py:204/220）      | 测试隔离用                              | 改 `WBM_MARKET_ROOT` / `WBM_HOME`，旧名走 §2.1 的 deprecated 通道                          |

| **代码符号** `GHPM_PY`（market_core.py:225，market_server.py:400-408）    | 指向 ghpm skill 脚本的**本机路径常量**，不是环境变量 | 符号改名 `REMOTE_JOB_TOOL`，语义注释改为「可选的远端任务执行器；缺失时远端任务功能停用」。**评审把它当环境变量是不准确的**，方案按代码符号处理 |

`_run_ghpm()`（market_server.py:385）改名 `run_remote_tool()`，  
`__GHPM__` 进度事件前缀保留（那是 ghpm 脚本的输出协议，不属于本项目对外 API），  
在 jobs.py 里加一行注释说明这是外部协议适配。

## 7. P0-⑥/⑦：测试迁移 + 消灭 2 个 SKIP

### 7.1 SKIP 核对结果

`sk(` 共 3 处，不是评审说的 2 处：

- **selftest.py:807** 「前端页面 token 注入」、**:838** 「首页可访问/口令注入」——这就是那 2 个常驻 SKIP。
- **selftest.py:1888** 「\_drop_link 实测」——环境条件跳过（本机建不出重解析点），**在 GitHub Actions 的 windows runner 上可以真正执行**（CI 允许建 junction），属于「本地 skip、CI 必跑」，不算欠账。

### 7.2 消掉前两个 SKIP（不需要浏览器）

现逻辑依赖 token 注入 HTML。改为纯 HTTP 断言，直接落在现有 `hit()` 基础设施上：

```python
conn.request("GET", "/")
resp = conn.getresponse()
body = resp.read().decode("utf-8", "replace")
assert resp.status == 200
assert "__MARKET_TOKEN__" not in body          # 占位符必须已被替换
assert "X-Local-Market-Token" not in body      # 口令头不出现在页面正文
assert TOKEN not in body                        # 完整口令绝不落进 HTML
```

保留一个 Playwright 用例放在 `tests/ui/`（`@pytest.mark.ui`，CI 里 `if: false` 手动触发）。

### 7.3 selftest → pytest 分批策略

2320 行 selftest 按 `run / round4 / round5 / round6 / round7 / faults / check_real`  
七段天然切分，映射：

| selftest 段落                                             | 去向                                                    |
| ------------------------------------------------------- | ----------------------------------------------------- |
| prepare_fixture + ck/sk/section 基建                      | `tests/conftest.py`（fixture + 自定义断言助手）                |
| run() 前 3 段（config/validate/hash/scan/lock）             | `tests/unit/`                                         |

| faults()（crash 注入/fail-closed/并发，selftest.py:1019-1540） | `tests/fault/`                                        |

## 11. 已知风险与未决问题

1. **monkeypatch 断链**（§3.2）——R2-R5 最大的回归风险，测试搬迁必须与实现搬迁同批。
2. **`.trash/.index.json` 迁移**：trash 索引里的相对路径语义在搬家后要复核  
   （`_trash_entry()` 只认 basename，理论安全，但要有迁移用例实证）。

   要同步 web/index.html，或先双写后下线。
4. **老用户升级路径**：v2.6 的 repo 根运行时文件如何迁移已在 §2.3 覆盖；  
   但「两个市场共用一个 STATE_HOME」的场景（STATE_HOME 未设 + 两个 clone）  
   会在 R1 引入共享锁/共享 trash——需要决定：默认 STATE_HOME 追加  
   market 名字子目录，还是保持 per-root。**建议 R1 评审时定案**，本文先按  
   「STATE_HOME/<market_name>/ 分桶」记为倾向方案。
5. LICENSE 代码来源核查：`plugins/` 内容是本机 skill 的打包副本，  
   开源公开前必须逐 skill 确认授权允许再分发（评审第 11 节的提醒，**这是比代码更硬的门槛**）。
