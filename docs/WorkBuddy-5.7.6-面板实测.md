# WorkBuddy 5.7.6 面板实测：本机插件市场在哪里、和原生界面比有什么优劣

> 实测环境：WorkBuddy 5.7.6（Windows）｜日期：2026-10-07
> 结论适用于写作时的 5.7.6；后续版本界面可能变化，欢迎用 issue 补充其他版本的实测。

## 一、面板结构：三个标签页，各吃各的数据源

左侧边栏「专家 技能·连接器」进去后是三个标签页。实测每个标签页的数据来源是固定的：

| 标签页 | 数据来源 | 实测观察 |
|---|---|---|
| 专家 | `cb_teams_marketplace`（官方）+ 服务端数据 | 专家团 / 专家卡片 |
| 技能 | **「用户自定义」**（扫 `~/.workbuddy/skills/`）+ **「来自市场」**（官方市场插件） | 用户自定义卡片带开关；来自市场的卡片带「插件」徽章 |
| 连接器 | `workbuddy-connector-plugins-official`（官方，317 个连接器） | 右上只有「自定义连接器」按钮 |

关键事实：**三个页面都没有「市场来源」下拉框**。自定义市场不会以
「本机插件市场」之类的板块单独露出。

## 二、那么本机插件市场在哪？

**在幕后。** 它的可见形态是技能页「用户自定义」里那排 skill 卡片：

- 注册信息写在 `~/.workbuddy/plugins/known_marketplaces.json`
  （一条 `wb-local-market` 记录，指向仓库目录）。
- 通过网页界面安装后，skill 复制进 `~/.workbuddy/skills/`，
  技能页扫到就显示为「用户自定义」卡片，带开/关切换。
- 实测：14 张用户自定义卡片 = 网文创作套件（story × 12）+ GitHub 项目管理
  + 浏览器自动化（CDP），与 skills 目录内容完全吻合。

一句话：**技能页能看到市场装进来的 skill，就说明市场在正常工作。**
市场本身不露脸，安装 / 卸载 / 更新走 `一键启动.cmd` 的网页界面。

## 三、和原生界面比，优劣各在哪

原生界面给不了、而本机市场能给的：

1. **私有 skill 有处安放。**「来自市场」只认官方源，自己写的 skill 想进
   WorkBuddy，要么手动拷文件夹，要么走本机市场——后者是唯一带管理的途径。
2. **一键装一套。** 12 个 story skill 在市场里是 1 张卡片，点一次全装好。
3. **能卸载、有托管。** 市场记录「哪个 skill 是我装的」，卸载只动自己的、
   不碰别人的；原生界面里用户自定义 skill 只有开关，没有卸载。
4. **安全网。** 事务日志、SHA-256 校验、回收站、崩溃恢复、软链/junction
   防护、跨进程文件锁——手动拷贝和原生安装都没有这套东西。
5. **市场是仓库不是镜像。** 源 skill 删了也能从市场装回来；
   `--sync` 一条命令把本机 skill 最新版重新打包同步。
6. **可分发。** 仓库开源，别的机器 clone 后跑一次 `一键启动.cmd` 即可复刻。

原生界面仍占优的地方（诚实说）：

- 官方市场插件支持自动更新（`autoUpdate: true`）；本机市场更新需重跑启动脚本。
- 原生开关交互开箱即用；本机市场的操作入口在它自带的网页里。
- 界面上看不出 skill 的「来路」（来自哪个市场/谁装的），这也是很多人
  「找不到本机市场」的直接原因。

## 四、操作速查

| 想做什么 | 去哪做 |
|---|---|
| 安装 / 卸载 / 更新 skill | `一键启动.cmd` 的网页界面（方式 B） |
| 确认注册状态 | `python launcher.py --status`（应显示「已注册」） |
| 在 WorkBuddy 里用 | 技能页 → 用户自定义，开卡片开关 |
| 摘掉整个市场 | `撤销注册.cmd` |
