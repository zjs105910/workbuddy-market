# 真实宿主验收清单（Windows 10/11 + WorkBuddy）

> 目的：证明「一个没有开发环境残留的新用户，从下载到卸载的完整旅程」可用。
> 本清单与 release-smoke 工作流互补：CI 能证明发行包可安装可体检，
> 只有真实宿主能证明 WorkBuddy 面板集成、多实例共存和恢复行为。
> 记录方式：每项后写 ✅/❌ + 一句话现象；❌ 项附截图或完整报错文本。

## 0. 环境要求（越干净越有价值）

- Windows 10 或 11，**未装过 Python / Git / Node 等开发工具**（虚拟机 fresh 镜像即可）。
- 已安装 WorkBuddy 桌面端（记录具体版本号：______）。
- 记录：机器内存 / 是否企业域管控 / 杀毒软件（ Defender 之外的会误拦 .cmd）。

## 1. 首次安装（源码 ZIP 路径）

| # | 操作 | 预期结果 |
|---|------|---------|
| 1.1 | 从 Releases 最新版下载 `WorkBuddy Market vX.Y.Z` 的 Source code (zip) | 浏览器正常下载，无安全拦截 |
| 1.2 | 右键解压到 `D:\wbm-test\` 之类的短路径 | 解压无报错 |
| 1.3 | 未装 Python 时双击 `安全模式-只开网页.cmd` | 提示缺 Python 且给出明确安装指引（不是裸 traceback） |
| 1.4 | 装 Python 3.10+（python.org 安装包，勾选 Add to PATH）后再双击 | 首次启动向导出现，环境检查 0/4 起步 |
| 1.5 | 向导中直接回车（只浏览模式） | 配置自动初始化，网页打开，能浏览社区目录 |
| 1.6 | 关闭网页与窗口，重新双击 | 二次启动无重新初始化，直接进入 |

## 2. WorkBuddy 接入

| # | 操作 | 预期结果 |
|---|------|---------|
| 2.1 | 双击 `一键启动.cmd`，向导中输入 `2` 注册 | 打包自检通过后注册成功，提示刷新 WorkBuddy |
| 2.2 | WorkBuddy 插件面板查看 | 市场条目出现，图标/名称正确 |
| 2.3 | **重启 WorkBuddy** | 市场条目仍在（注册持久化） |

## 3. 技能安装 / 更新

| # | 操作 | 预期结果 |
|---|------|---------|
| 3.1 | 面板中安装一个社区技能 | 安装前四问（来源/权限/兼容/体积）出现，确认后落位到 skills 目录 |
| 3.2 | 到文件管理器核对落位目录 | 目录结构与注册表声明一致 |
| 3.3 | 对同一技能触发更新 | 更新后版本/哈希状态与注册表一致，「可更新」不残留假阳性（v2.27 修复回归点） |
| 3.4 | 手工改一个已装技能的文件再触发更新 | 检测到内容被改，**不得静默洗白**，冲突显式提示 |

## 4. 卸载与恢复

| # | 操作 | 预期结果 |
|---|------|---------|
| 4.1 | 卸载 3.1 安装的技能 | 文件进回收站（可恢复），skills 目录不再有它 |
| 4.2 | 从回收站/恢复功能还原 | 技能完整回来，SHA-256 与安装时一致 |
| 4.3 | 在 skills 目录自建一个非市场技能，然后全量卸载/清理 | **自己的技能不被误删**（所有权分级回归点） |

## 5. 多实例共存（v2.29 marketId 修复回归，重点）

| # | 操作 | 预期结果 |
|---|------|---------|
| 5.1 | 同一机器再解压一份 v2.29.0 到另一目录，走完向导注册 | 两份市场同时出现在 WorkBuddy，互不覆盖（v2.29 起每份有唯一 marketId） |
| 5.2 | 检查 `%USERPROFILE%\.workbuddy\plugins\known_marketplaces.json` | 两个条目并存，key 不同，installLocation 各指各的 |
| 5.3 | 注销其中一份（`launcher.py --unregister`） | **只删自己那个 key**，另一份注册原封不动（v2.29 前会误删共享 key） |
| 5.4 | 老版本升级场景：已有 v2.28.0 注册（marketId=wb-local-market）的机器装 v2.29.0 并注册 | v2.29 冲突守卫拒绝同名 key 冲突并给出人话提示，不静默覆盖旧注册 |
